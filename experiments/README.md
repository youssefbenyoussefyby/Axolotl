# Experiments

This directory holds the research experiments that use AxolotlDB as a testbed. The
directions and their motivation are in [`docs/research/RESEARCH.md`](../docs/research/RESEARCH.md).
Here the focus is method: each experiment is written down before it runs, and every
result can be reproduced from the repository.

## Layout

```
experiments/
├── README.md              this protocol
├── TEMPLATE.md            copy this to start a new experiment
├── E001-semantic-filter-ordering/
│   └── README.md          hypothesis, baseline, metric, procedure, results
└── results/
    └── E001/<git-sha>/    raw outputs: config.json, results.csv, environment.txt
```

Tooling: [`tools/record_env.py`](../tools/record_env.py) `E###` creates
`results/E###/<short-sha>/` and writes `environment.txt` (protocol step 3). Generated
datasets live in each experiment's `data/` directory, which is git-ignored: commit the
generator and its seed, not the data.

Experiments are numbered `E###` in creation order and never renumbered. An abandoned
experiment stays in the tree with its status set to `abandoned` and a sentence on why.
Negative results count as results.

## Protocol

1. **Pre-register.** Fill in the hypothesis, baseline, metrics and procedure in the
   experiment's `README.md` and commit it *before* collecting results. If the plan
   changes after data is seen, record the change and the reason in the README's
   "Deviations" section rather than editing the original plan.
2. **Pin everything.**
   - Fixed random seeds, written into `config.json`.
   - Datasets are either committed (small), generated by a committed script with a seed,
     or fetched from a stable URL with a recorded checksum.
   - Model calls record the provider, model ID, prompt template version and temperature.
     Cache responses on disk (keyed by prompt hash), so a rerun can replay them without
     calling the model again.
3. **Record the environment.** Every run writes `environment.txt` with the git SHA
   (`git rev-parse HEAD`), a dirty-tree flag, compiler and version, build type, OS, CPU,
   and the date.
4. **Commit results under the SHA that produced them**:
   `results/E###/<short-sha>/`. A changed result then shows up as a diff, and an old
   result can always be traced back to its code.
5. **Check correctness before speed.** Any plan or operator variant is cross-validated
   against the baseline plan: both must return the same rows (as a multiset) on every
   query before their costs are compared. This is the technique the engine already uses
   for joins (`JoinTest.HashJoinAgreesWithNestedLoopOnSameInput`).
6. **Report the distribution, not the best run.** For latency, use the median and
   p95 over at least 5 repetitions after warm-up. For model-dependent quality metrics,
   report the mean and spread over at least 3 seeds.
