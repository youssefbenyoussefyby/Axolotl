# P10 — Embeddings (M, optional)

Text in, vectors out — a provider interface, an external default, and an optional ONNX
Runtime implementation behind a build flag.

**Moved last and made optional**, and both parts are deliberate. It is the only phase adding
no database machinery, and it pulls ONNX Runtime — ~200 MB of platform-specific binaries with
no clean FetchContent story — for what is a thin client of [P7](P7.md).

**The interface is declared in [P7](P7.md)**, so the vector path is complete without this
phase ever running. **Not doing P10 is a valid outcome.** If you do it, `ENABLE_ONNX=OFF`
must stay the default and the build must stay clonable either way.

**Depends on:** [P7](P7.md) · **Blocks:** nothing ·
**ROADMAP:** [§5 P10](../ROADMAP.md#p10--embeddings-m-optional)

---

## Before you start — the minimum

1. **Decide whether to do this phase at all.** Read
   [§5 P10](../ROADMAP.md#p10--embeddings-m-optional) again. `ExternalEmbeddingProvider` —
   the client computes embeddings, the database stores and searches them — is the default and
   it demonstrates everything. The ONNX half buys "embeddings computed in-process" at the
   cost of a 200 MB platform-specific dependency in a project whose build currently clones
   and compiles anywhere. That trade is the phase.
2. **[ONNX Runtime C++ API](https://onnxruntime.ai/docs/api/c/)** — only if doing 10.5.
   The `Ort::Session` / `Ort::Value` lifetime model, and the tensor shape conventions.
3. **[Sentence Transformers documentation](https://sbert.net/)** — what an embedding model
   actually expects: tokenisation, attention masks, and **pooling**. Mean pooling over the
   last hidden state, and L2 normalisation afterwards, are the two steps most easily got
   wrong — and they fail *silently*, as mediocre recall rather than an error.

## Resources

### Specs & docs

- **[ONNX Runtime C++ API](https://onnxruntime.ai/docs/api/c/)** and
  **[install guide](https://onnxruntime.ai/docs/install/)** — the binaries, per platform.
- **[ONNX Runtime GitHub releases](https://github.com/microsoft/onnxruntime/releases)** —
  what "no clean FetchContent story" means concretely: prebuilt archives per OS and
  architecture, not a source build you can add as a subdirectory.
- **[Hugging Face: Exporting to ONNX](https://huggingface.co/docs/transformers/serialization)**
  — how a model becomes the `.onnx` file 10.5 loads.
- **[sentence-transformers/all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)**
  — 384 dimensions, small, permissively licensed, and the standard first choice. Its model
  card documents the exact pooling it expects.
- **[tokenizers](https://github.com/huggingface/tokenizers)** — the tokenisation half, which
  ONNX Runtime does **not** do for you. This is the part people underestimate: a wrong
  tokeniser produces plausible vectors with poor recall and no error anywhere.

### Books

None. This is an integration phase.

### Video

None that maps. If unfamiliar with embeddings as a concept, any introduction to sentence
embeddings will do; the database-side work here is thin by design.

### Code to read

- **[pgvector](https://github.com/pgvector/pgvector)** — note what it does *not* do: it
  stores and searches vectors and leaves embedding generation entirely to the client. That
  is `ExternalEmbeddingProvider`, and it is the design the most successful project in this
  space chose.
- **[llama.cpp](https://github.com/ggml-org/llama.cpp)** `examples/embedding` — if
  in-process embedding is genuinely wanted, GGUF plus llama.cpp is a lighter dependency than
  ONNX Runtime and worth evaluating before committing to 10.5.

### Skip

- **Model training or fine-tuning.** Entirely out of scope.
- **GPU inference.** ONNX Runtime's CUDA/DirectML providers. If ONNX is already a marginal
  call, GPU is not one.
- **Reranking, cross-encoders, RAG orchestration.** Application concerns; the database's job
  ends at "returns the k nearest".
- **Multiple model formats.** One ONNX path, or none.

## Implementation checklist

### 10.1 — The interface (already declared in P7)

- [ ] Confirm `IEmbeddingProvider` exists from [P7 item 7.2](P7.md#72--the-vectorindex-interface):
      `Embed`, `EmbedBatch`, `Dimension`
      → `include/vector/embedding.h`
- [ ] A `FakeEmbeddingProvider` for tests — deterministic vectors from a hash of the input,
      so every test below runs with no model and no network
      → `tests/fixtures/fake_embedding_provider.h`
      → test: `EmbeddingTest.FakeProviderIsDeterministic`
- [ ] Dimension mismatch between provider and target column throws, reusing
      `VectorDimensionMismatchException`
      → [`include/utils/errors.h`](../../include/utils/errors.h)
      → test: `EmbeddingTest.ProviderDimensionMustMatchColumnDimension`

### 10.2 — ExternalEmbeddingProvider

The default, and the one that demonstrates the whole phase.

- [ ] Accept precomputed vectors through the SQL and wire surfaces — a client that already
      has embeddings needs no provider at all
      → `src/vector/embedding.cpp`
      → test: `ExternalProviderTest.PrecomputedVectorIsStoredVerbatim`
- [ ] Optional HTTP call-out to an embedding endpoint, with the URL configured through
      `ConfigManager` and `AxolotlDB_*` env overrides like every other setting
      → `src/utils/config.cpp`
      → test: `ExternalProviderTest.EndpointIsConfigurable`,
        `ExternalProviderTest.UnreachableEndpointFailsWithADiagnosableError` — not a
        hang, and not a silent zero vector
- [ ] Never block a write path indefinitely: timeouts, with the failure surfacing as a
      statement error
      → test: `ExternalProviderTest.TimeoutSurfacesAsStatementError`

### 10.3 — Auto-embed on INSERT

- [ ] Column-level configuration: a VECTOR column can name a source text column
      → `src/catalog/catalog.cpp`
      → test: `CatalogTest.EmbeddingSourceColumnSurvivesReopen`
- [ ] `InsertExecutor` calls the provider when the vector column is absent from the
      statement but its source column is present
      → `src/executor/operators/insert.cpp`
      → test: `AutoEmbedTest.InsertWithoutVectorPopulatesItFromSourceColumn`,
        `AutoEmbedTest.ExplicitVectorOverridesAutoEmbed`,
        `AutoEmbedTest.NullSourceTextLeavesVectorNull`
- [ ] `UpdateExecutor` re-embeds when the source column changes — and **not** when it does
      not, because re-embedding on every update is both slow and a silent index churn
      → `src/executor/operators/update.cpp`
      → test: `AutoEmbedTest.UpdatingSourceTextReEmbeds`,
        `AutoEmbedTest.UpdatingAnUnrelatedColumnDoesNotReEmbed`
- [ ] A provider failure aborts the transaction rather than storing a wrong vector
      → test: `AutoEmbedTest.ProviderFailureAbortsTheInsert`

### 10.4 — Batch embedding

- [ ] `EmbedBatch` used for multi-row `INSERT ... VALUES` and bulk load
      → `src/vector/embedding.cpp`
      → test: `BatchEmbedTest.MultiRowInsertIssuesOneBatchCall` — assert the call count
        on a spy provider; the whole point is one call, not N
      → test: `BatchEmbedTest.BatchResultsMapToTheCorrectRows` — an off-by-one in the
        mapping assigns everyone their neighbour's embedding, which is silently wrong
        in exactly the way [P1's lesson 2](P1.md#2-silent-wrong-answers-are-the-failure-mode-to-engineer-out)
        warns about
- [ ] A configured maximum batch size, with larger inputs chunked
      → test: `BatchEmbedTest.OversizedInputIsChunked`

### 10.5 — OnnxEmbeddingProvider (behind `ENABLE_ONNX=OFF`)

- [ ] `ENABLE_ONNX` CMake option, **defaulting to OFF**, with ONNX Runtime discovery that
      fails with a clear message rather than a link error
      → `CMakeLists.txt`, `cmake/FindONNXRuntime.cmake`
      → verify: `cmake -DENABLE_ONNX=ON` without the runtime present prints a
        diagnosable message
- [ ] Tokenisation. **Do not skip this or approximate it** — a wrong tokeniser yields
      plausible vectors with quietly poor recall
      → `src/vector/embedding.cpp`
      → test: `OnnxProviderTest.TokenizerMatchesReferenceOutputForFixedStrings` —
        golden values generated once from the reference implementation and committed
- [ ] `Ort::Session` load, run, and the tensor shape conventions
      → test: `OnnxProviderTest.EmbedReturnsDeclaredDimension`
- [ ] Pooling and normalisation, matching the model card
      → test: `OnnxProviderTest.MeanPoolingMatchesReferenceVectors` — cosine similarity
        against committed reference vectors, within tolerance. Without this the
        provider "works" and the recall is mysteriously bad
- [ ] Thread safety: one `Ort::Session` shared across [P9](P9.md)'s sessions, or one each,
      with the choice documented
      → test: `OnnxProviderTest.ConcurrentEmbedCallsAreSafe`
- [ ] Model path and thread count through `ConfigManager`
      → `src/utils/config.cpp`

### 10.6 — Keep the build clonable

The constraint that makes this phase safe to attempt.

- [ ] Every test in 10.1–10.4 passes with `ENABLE_ONNX=OFF`, using `FakeEmbeddingProvider`
      → verify: `ctest` green in a clean clone with no model and no network
- [ ] The `docker` CI surface builds with ONNX off and stays its current size
      → `Dockerfile`
- [ ] `models/` is gitignored, or holds only a documented download script — never a
      committed model binary
      → `.gitignore`, `models/README.md`
- [ ] Document the ONNX build in `README.md` as opt-in, with the platform caveats stated
      plainly rather than discovered

## Gate

[§5 P10](../ROADMAP.md#p10--embeddings-m-optional) states no explicit gate. Deriving one
that respects the phase's optionality:

- [ ] **text → vector → ranking** end to end: insert rows carrying text, embeddings
      generated by the provider, a KNN query returns them in an order the test verifies
      independently
      → `tests/integration/embedding_test.cpp`
      → test: `EmbeddingGate.TextToVectorToRankingWithFakeProvider` — **runs with
        `ENABLE_ONNX=OFF`**, so the gate is meaningful in the default build
- [ ] With `ENABLE_ONNX=ON`, the same test passes against a real model
      → test: `EmbeddingGate.TextToVectorToRankingWithOnnxProvider` — guarded by the
        build flag, and **not** part of the seven-surface requirement

## Done when

1. [ ] The gate test passes with `ENABLE_ONNX=OFF`, and demonstrably failed before the work.
2. [ ] All seven CI surfaces green **with ONNX off** — the default build is the one that
       must stay green. The ONNX path is verified in a separate, optional job.
3. [ ] No new compiler warnings; ASan and UBSan clean.
4. [ ] [ROADMAP §1.1](../ROADMAP.md#11-the-one-page-table) updated.

## Or: don't

Ticking nothing on this page is a legitimate end state for the project. [P7](P7.md) delivers
a working vector database; P10 delivers a convenience that most production systems in this
space — pgvector included — deliberately leave to the client.
