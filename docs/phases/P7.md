# P7 — Vector indexing / ANN (XL)

The phase this database exists for. Exact KNN first, then HNSW, with a persisted graph.

**Build brute-force KNN first, and it is not a throwaway.** A linear scan over `VectorHeap`
computing exact distances is a day's work. It makes the vector path end-to-end queryable
immediately — and, critically, **it is the ground truth.** "The HNSW index works" is a
meaningless claim without a recall number, and recall is *defined* as agreement with the
exact nearest neighbours. Brute force is the oracle every later HNSW test needs.

**Depends on:** [P2](P2.md), [P4](P4.md), [P5](P5.md) · **Blocks:** [P10](P10.md) (optional) ·
**ROADMAP:** [§5 P7](../ROADMAP.md#p7--vector-indexing--ann-xl)

## Before you start — the minimum

1. **Malkov & Yashunin, [*Efficient and robust approximate nearest neighbor search using
   Hierarchical Navigable Small World graphs*](https://arxiv.org/abs/1603.09320).** Read
   Algorithms 1–5 — they are pseudocode, and they are the whole implementation. §4's
   parameter discussion (`M`, `ef_construction`, `ef`, `mL`) is what 7.5 tunes. The
   neighbour-selection heuristic (Algorithm 4) is the part that separates a working index
   from one with poor recall, and it is easy to skip on a first read.
2. **15-445 Fall 2025, Lecture 9 — Indexes & Filters II**, vector-index section. Short, and
   it frames where ANN sits relative to B+Trees. The paper does the real work.
3. **[hnswlib](https://github.com/nmslib/hnswlib) `hnswlib/hnswalg.h`.** Header-only,
   ~1000 lines, by one of the paper's authors. Read `searchBaseLayer` and
   `getNeighborsByHeuristic2` alongside Algorithms 2 and 4. It is entirely in-memory, which
   is precisely the constraint 7.7 removes.

### Code to read

- **hnswlib `hnswalg.h`** — the algorithm, in memory.
- **pgvector `src/hnsw*.c`** — the algorithm, on pages, in a WAL.

### Skip

- **IVF / IVF-PQ / product quantisation.** [§5 P7](../ROADMAP.md#p7--vector-indexing--ann-xl)
  marks IVF **optional**, and `src/vector/ivf/ivf_index.cpp` can stay empty. FAISS's
  quantisation machinery is a large, self-contained subject that buys memory footprint —
  a concern this project does not have yet.
- **GPU acceleration.** FAISS's `gpu/` tree. Not a thing here.
- **Learned indexes, DiskANN, SPANN, ScaNN.** Interesting; each is its own project.
- **Rebuild-on-load as the destination.** It stays as an *early milestone* (7.6) and
  nothing more — see [amendment #4](../ROADMAP.md#7-amendment-log).
- **Deletion with graph repair.** Tombstones only, per
  [§5 P7](../ROADMAP.md#p7--vector-indexing--ann-xl) — the same accepted debt as B7 and
  `VectorHeap` itself, and consistent rather than a new pattern.

## Design decisions already made

| Decision | Where | Why |
|---|---|---|
| Brute force first, and it stays as the oracle | [§5 P7](../ROADMAP.md#p7--vector-indexing--ann-xl) | Recall is *defined* as agreement with exact NN |
| Graph persisted as a second fixed-stride heap | [§5 P7](../ROADMAP.md#p7--vector-indexing--ann-xl), amendment #4 | An HNSW node's neighbour list is `M` entries per layer — a fixed-stride record, which `VectorHeap` already implements and has 43 tests for |
| Rebuild-on-load is a milestone, not the destination | amendment #4 | A million 1536-dim vectors is minutes of startup — slow enough that nobody runs the restart gate test, which is the test that catches persistence bugs |
| Deletes are tombstones | [§5 P7](../ROADMAP.md#p7--vector-indexing--ann-xl) | Consistent with B7 and `VectorHeap`; graph repair is a separate project |
| Vector data pages already carry the standard header | [N9](../ROADMAP.md#n9--vectorheap-data-pages-have-nowhere-to-put-a-page_lsn) option A, landed in [P2](P2.md) | *"This is the mechanical reason WAL cannot wait until after HNSW"* — the graph inherits a layout that already recovers |

## Implementation checklist

### 7.1 — Distance kernels

- [ ] `DistanceMetric` enum and `Distance(span<const float>, span<const float>, metric)`
      → `include/vector/distance.h`, `src/vector/distance.cpp`
- [ ] A **scalar reference implementation**, kept, and used to validate the SIMD path
      → test: `DistanceTest.SimdAgreesWithScalarWithinTolerance` — the same
        cross-validation pattern used for the joins in [P4](P4.md). Without it, a SIMD
        bug shows up as *slightly worse recall*, which is indistinguishable from
        normal ANN behaviour and therefore effectively invisible
- [ ] L2, cosine and inner product
      → test: `DistanceTest.L2OfIdenticalVectorsIsZero`,
        `DistanceTest.CosineOfOrthogonalVectorsIsOne`,
        `DistanceTest.InnerProductSignConvention` — document whether larger is better
        and assert it; getting this backwards silently inverts every result
- [ ] Eigen-backed SIMD kernels
      → test: `DistanceTest.HandlesDimensionsNotMultipleOfSimdWidth` — the tail
        elements, e.g. dimension 769
- [ ] Dimension mismatch throws, reusing `VectorDimensionMismatchException`
      → [`include/utils/errors.h`](../../include/utils/errors.h)
      → test: `DistanceTest.DimensionMismatchThrows`

### 7.2 — The VectorIndex interface

- [ ] `Neighbor { VectorId id; float distance; }` and `VectorIndex` with `Add` and `Search`
      → `include/vector/vector_index.h`
      → test: `VectorIndexTest.SearchReturnsAtMostK`,
        `VectorIndexTest.ResultsAreSortedByDistance`
- [ ] `IEmbeddingProvider` **declared here**, so the vector path is complete without
      [P10](P10.md) ever running
      → `include/vector/embedding.h`

### 7.3 — BruteForceIndex, the oracle

- [ ] Linear scan over `VectorHeap` computing exact distances
      → `src/vector/vector_index.cpp`
      → test: `BruteForceTest.FindsTheExactNearestNeighbour`,
        `BruteForceTest.KGreaterThanCorpusReturnsEverything`,
        `BruteForceTest.EmptyHeapReturnsNothing`,
        `BruteForceTest.TiedDistancesHaveDeterministicOrdering` — ties must break
        deterministically or the recall measurement in 7.9 becomes noisy
- [ ] Ground-truth generator: fixed dataset, fixed seed, precomputed top-k
      → `tests/fixtures/vector_ground_truth.cpp`
      → test: `BruteForceTest.GroundTruthIsReproducibleAcrossRuns`

### 7.4 — Query path, on brute force alone

After this item the vector path is **end-to-end queryable**. Commit it as a milestone, the
same way [P4 item 4.2](P4.md#42--the-milestone-seqscan--filter--projection) is one.

- [ ] KNN operator inside [P4](P4.md)'s executor framework
      → `src/executor/operators/vector_search.cpp`
      → test: `KnnTest.ReturnsKNearestFromRealFiles`
- [ ] SQL surface for it in the parser, binder and planner — an `ORDER BY <dist> LIMIT k`
      form or an explicit function; **pick one and write down which**
      → `src/parser/parser.cpp`, `src/parser/binder.cpp`
      → test: `ParserTest.VectorSearchStatement`
- [ ] Hybrid `filter + vector`: predicate first then KNN, or KNN then predicate
      → test: `KnnTest.HybridFilterReturnsKMatchingRowsNotKThenFiltered` — the
        classic wrong answer is filtering *after* taking the top k, which returns
        fewer than k rows and looks almost right

### 7.5 — HNSW, in memory

Follow the paper's algorithm numbering; each maps to an item.

- [ ] Layer assignment with the exponentially decaying distribution (`mL`), seeded for
      reproducibility in tests
      → `src/vector/hnsw/hnsw_graph.cpp`
      → test: `HnswTest.LayerDistributionMatchesExpectedDecay`
- [ ] Algorithm 2 — `SEARCH-LAYER`, the greedy beam search with `ef`
      → `src/vector/hnsw/hnsw_search.cpp`
      → test: `HnswTest.SearchLayerReturnsEfCandidates`
- [ ] Algorithm 1 — `INSERT`, descending from the top layer
      → `src/vector/hnsw/hnsw_index.cpp`
      → test: `HnswTest.SingleElementIndexReturnsThatElement`,
        `HnswTest.EntryPointUpdatesWhenANodeGetsAHigherLayer`
- [ ] Algorithm 4 — the neighbour-selection **heuristic**, not plain top-M. This is the
      item that determines whether recall is 0.95 or 0.70
      → test: `HnswTest.HeuristicSelectionBeatsNaiveTopMOnRecall` — assert the
        comparison directly, so the heuristic's value is visible and a later
        "simplification" cannot quietly remove it
- [ ] Algorithm 5 — `K-NN-SEARCH`
      → test: `HnswTest.RecallAgainstBruteForceExceedsThreshold` — on a small fixture,
        as a fast feedback loop long before the gate
- [ ] Bidirectional edges and the `M`/`Mmax0` pruning on the base layer
      → test: `HnswTest.NoNodeExceedsMmaxNeighbours`,
        `HnswTest.GraphIsConnectedFromEntryPoint` — a disconnected graph is the
        classic HNSW bug, and it degrades recall rather than failing outright

### 7.6 — Rebuild-on-load milestone

Explicitly a stepping stone, not the destination.

- [ ] Reconstruct the graph by re-`Add`ing every vector from the `VectorHeap` on open
      → test: `HnswTest.RebuiltIndexMatchesOriginalRecall`
- [ ] Measure and record the rebuild time at 100k vectors, as the evidence for why 7.7
      is necessary
      → `benchmarks/vector_bench`

### 7.7 — Persisted graph

- [ ] Neighbour-list record layout: `M` entries per layer — a fixed-stride record, so
      reuse `VectorHeap`'s addressing rather than inventing a second scheme
      → `src/vector/hnsw/hnsw_graph.cpp`
      → test: `HnswGraphTest.NodeRecordLayoutIsStable` — raw bytes
- [ ] Graph header page: entry point, max layer, `M`, `ef_construction`, metric, element
      count. **Element count written last, as the commit point** — the same discipline
      `VectorHeap`'s `Sync()` uses ([§4.4](../ROADMAP.md#44-vectorheap-file))
      → test: `HnswGraphTest.CountIsTheCommitPoint`
- [ ] Variable layer counts over a fixed-stride layout — either a per-layer heap or a
      worst-case allocation. **Write down which and why**
      → test: `HnswGraphTest.HighLayerNodeRoundTrips`
- [ ] `ValidateOrThrow` for graph records: neighbour ids in range, layer counts sane.
      [P1's lesson 1](P1.md#1-trust-nothing-that-came-off-disk) for the third time
      → test: `HnswGraphTest.NeighbourIdBeyondElementCountThrows`
- [ ] WAL records for graph mutation, using [P5](P5.md)'s `LogManager`
      → test: `HnswRecoveryTest.InsertSurvivesCrash`,
        `HnswRecoveryTest.CrashMidInsertLeavesAValidGraph`
- [ ] Deletes as tombstones, skipped during search
      → test: `HnswTest.TombstonedVectorIsNeverReturned`,
        `HnswTest.SearchStillReturnsKWhenTombstonesArePresent`

### 7.8 — Benchmarks

- [ ] `benchmarks/vector_bench` against a fixed ground-truth set
      → `benchmarks/vector_bench/main.cpp`
- [ ] Recall@k and latency across `ef` values, producing the recall-vs-QPS curve
      ANN-Benchmarks uses
- [ ] Build time and index size vs `M` and `ef_construction`
- [ ] Numbers recorded in the repo so a regression is visible as a diff, not a memory
      → `benchmarks/vector_bench/RESULTS.md`
