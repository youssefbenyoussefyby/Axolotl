# P2 — Storage services (L)

The missing layer. `Page` gives you 4096 bytes; a query engine needs tables, rows addressed
by RID, iteration, and a catalog. Nothing above this can start until it exists — P3's binder
resolves names against the catalog, P4's SeqScan iterates a `TableHeap`, P6's B+Tree gets its
nodes from the `StorageManager`.

It is also where the two structural mistakes from P1 get fixed while they are still cheap:
one buffer pool instead of one per heap ([N6](../ROADMAP.md#n6--every-vectorheap-owns-a-private-filemanager-and-a-private-buffer-pool)),
and RAII pins instead of manual unpin ([N4](../ROADMAP.md#n4--pin-leaks-on-the-exception-paths-and-no-raii-to-prevent-them)).
Four call sites today; hundreds by P7.

**Depends on:** [P0](P0.md) · **Blocks:** P3–P10 ·
**ROADMAP:** [§5 P2](../ROADMAP.md#p2--storage-services-l)

**Order within the phase is not negotiable:** `StorageManager` → `PageGuard` → header
growth → `TableHeap` → `Catalog` → WAL contract. Each depends on the previous.

## Before you start — the minimum

1. **Hellerstein, Stonebraker & Hamilton, [*Architecture of a Database System*](https://dsf.berkeley.edu/papers/fntdb07-architecture.pdf),
   §4 (Relational Query Processor) and §5 (Storage Management).** ~25 pages. This is the map
   [ROADMAP §3.1](../ROADMAP.md#31-where-the-layers-sit-after-p2) is drawn from, and §5.3's
   treatment of the buffer pool as the single choke point is the argument for putting the
   WAL rule inside it rather than at call sites.
2. **15-445 Fall 2025, Lectures 3–5** — Database Storage I, Memory Management, Database
   Storage II ([schedule](https://15445.courses.cs.cmu.edu/fall2025/schedule.html) ·
   [playlist](https://www.youtube.com/playlist?list=PLSE8ODhjZXjYMAgsGH-GtY5rJYZ6zjsd5)).
   Lecture 4 is the buffer pool: page tables, page directories, and why the pool owns
   eviction policy rather than the OS.
3. **[BusTub](https://github.com/cmu-db/bustub)** — `src/include/storage/page/page_guard.h`
   and `src/storage/page/page_guard.cpp`. Read for *shape*: move-only, `Drop()`, the
   read/write split. Their `BufferPoolManager` also keys frames by `page_id_t` alone, which
   is exactly the limitation N6 is about — useful as a contrast, not a model.

### Skip

- **Log-structured / LSM storage.** Lecture 5's second half, and most of Petrov's later
  chapters. This is an in-place update engine; the comparison is interesting and changes
  nothing you will write.
- **Compression and column stores** (Lecture 6). [§6.3 non-goal](../ROADMAP.md#63-non-goals).
- **Implementing the WAL.** 2.7 lands the *contract* — `ILogManager` and a null
  implementation — and stops. [P5](P5.md) does the rest. Writing a real `LogManager` here
  means designing `TransactionManager` before the executor exists, which is guessing.
- **PostgreSQL's forwarding-tombstone HOT chains.** Relevant to `Update`, and explicitly not
  chosen — [§5 P2](../ROADMAP.md#tableheap) takes the RID-changing route instead. Reading
  about HOT will make you want to re-open a settled decision.

## Design decisions already made

| Decision | Where | Why it is not re-opened |
|---|---|---|
| One `BufferPool`, many files, keyed by packed `PageRef` | [N6](../ROADMAP.md#n6--every-vectorheap-owns-a-private-filemanager-and-a-private-buffer-pool) | `PageId` is file-local; one pool structurally cannot address two files |
| `FetchRead`/`FetchWrite`, not one `FetchPage(bool is_dirty)` | [§5 P2](../ROADMAP.md#storagemanager) | Moves the dirty decision from a droppable bool into the type |
| Guards are move-only | [§5 P2](../ROADMAP.md#pageguard) | A copied guard is a double unpin |
| `PageHeader` grows to 24 bytes | [§4.1](../ROADMAP.md#41-page--4096-bytes-fixed-at-compile-time) | 32-bit LSN wraps; 16-bit checksum collides 1-in-65536. 8 bytes is 0.2% |
| `Update` returns a possibly-new RID | [§5 P2](../ROADMAP.md#tableheap) | Makes the cost visible in the signature; P6 is the caller that must know |
| Vector data pages get the standard header (option A) | [N9](../ROADMAP.md#n9--vectorheap-data-pages-have-nowhere-to-put-a-page_lsn) | One recovery path, not two. Must land before HNSW inherits the layout |
| `HeapId` is monotonic and persisted, never reused | [§5 P2](../ROADMAP.md#catalog) | A reused id makes a stale `VectorRef` validate against the wrong heap |
| Format version byte, not reserved `begin_ts`/`end_ts` | [§5 P2](../ROADMAP.md#tuple-format-versioning), amendment #5 | 16 bytes/row forever for an out-of-scope feature |
