# P9 — Client / server / CLI (M)

Length-prefixed framing over asio, session management, a thread pool, and a real CLI REPL
replacing the current echo loop.

**Genuinely concurrent, because [P5](P5.md) delivered the page latch.** Without it this
phase would have had to serialise every query behind one global lock — which is
[amendment #3](../ROADMAP.md#7-amendment-log)'s reasoning, and the hole in the original plan
that moving B8 into P5 closed.

**Depends on:** [P4](P4.md) (something to execute), [P5](P5.md) (the latch, and
transactions per session) · **Blocks:** nothing ·
**ROADMAP:** [§5 P9](../ROADMAP.md#p9--client--server--cli-m)

---

## Before you start — the minimum

1. **[Asio overview and tutorial](https://think-async.com/Asio/asio-1.30.2/doc/asio/tutorial.html)**
   — asio is already a dependency. Work the daytime-server examples, then read the
   **[async model](https://think-async.com/Asio/asio-1.30.2/doc/asio/overview/model.html)**
   page. The asynchronous ownership rules (objects must outlive their handlers) are where
   asio servers actually break, and `shared_from_this` on the session is the standard
   answer.
2. **[Asio C++11 examples — HTTP server 3](https://think-async.com/Asio/asio-1.30.2/doc/asio/examples/cpp11_examples.html)**
   — the canonical `server`/`connection`/`connection_manager` decomposition. 9.2's structure
   is this, with a different framing layer.
3. **This project's [§6.2](../ROADMAP.md#62-naming--pick-one)** — the naming question.
   `Axolotl` / `AxolotlDB` / `AxolotlDB` / `AxolotException` are four spellings of one name,
   and **this is the phase where a name goes into a wire protocol and a CLI banner**.
   Settle it in item 9.7 before anything ships it.

## Resources

### Specs & docs

- **[Asio documentation](https://think-async.com/Asio/asio-1.30.2/doc/)** — overview,
  tutorial, and the C++11 examples. The reference for the whole phase.
- **[PostgreSQL: Frontend/Backend Protocol](https://www.postgresql.org/docs/current/protocol.html)**
  — read the **Message Flow** and **Message Formats** overview even though wire
  compatibility is a [non-goal](../ROADMAP.md#63-non-goals). It shows what a mature
  protocol has to carry (typed messages, error fields, ready-for-query sync points) and is
  worth borrowing *ideas* from while not implementing it.
- **[SQLite CLI documentation](https://sqlite.org/cli.html)** — dot-commands, output modes
  (`.mode table` / `json` / `csv`), and `.schema`. 9.5 implements a subset; this is the
  reference for what users expect.
- **[linenoise](https://github.com/antirez/linenoise)** or
  **[replxx](https://github.com/AmokHuginnsson/replxx)** — small, permissively licensed line
  editors giving history and editing. Writing your own is a distraction; replxx is
  cross-platform including Windows, which matters for `build-windows`.

### Books

None required. This is systems programming, not database theory, and the asio docs are
better than any book on it.

- **Optional:** *C++ Concurrency in Action*, Williams — ch 9 on thread pools, if 9.2's pool
  needs more than asio's `io_context` running on N threads (it probably does not).

### Video

No 15-445 lecture maps to this phase. If you want background on why wire protocols look the
way they do, the [CMU Database Group channel](https://www.youtube.com/@CMUDatabaseGroup)
seminar series has talks on database networking layers — optional.

### Code to read

- **Asio's `examples/cpp11/http/server3`** — thread-pool server, the closest template.
- **SQLite `shell.c`** — a complete, single-file database CLI. Large, but the output
  formatting and dot-command dispatch are worth lifting the *structure* of.

### Skip

- **PostgreSQL wire protocol compatibility.** Explicit
  [non-goal](../ROADMAP.md#63-non-goals): *"a compatibility project — weeks of message-format
  work with no database learning in it — unless `psql` compatibility is a goal worth naming.
  If it is, it belongs in its own phase."*
- **TLS.** Not in scope. If it ever is, asio's SSL streams make it additive.
- **Authentication and authorisation.** No user model exists. Do not invent one here; it is
  a phase, not a checkbox.
- **Connection pooling on the client side.** One connection per client is correct at this
  scale.
- **HTTP/REST or gRPC front ends.** A different product decision.

## Implementation checklist

### 9.1 — Wire protocol and framing

- [ ] Message types: `Query`, `RowDescription`, `DataRow`, `CommandComplete`, `ErrorResponse`,
      `ReadyForQuery` — the PostgreSQL *shape* without its byte format
      → `include/network/protocol.h`
- [ ] Length-prefixed framing: `uint32` length, `uint8` type, payload
      → `src/network/protocol.cpp`
      → test: `ProtocolTest.FrameRoundTrips`,
        `ProtocolTest.PartialFrameIsBuffferedUntilComplete` — a message split across
        two TCP reads is the normal case, not an edge case, and the first thing a
        naive framer gets wrong
      → test: `ProtocolTest.TwoFramesInOneReadAreBothDelivered`
- [ ] **A declared maximum frame size, enforced.** A length prefix off the wire is
      untrusted input — [P1's lesson 1](P1.md#1-trust-nothing-that-came-off-disk), now at
      the network boundary, where the input is not merely corrupt but potentially hostile
      → test: `ProtocolTest.OversizedLengthPrefixIsRejectedNotAllocated`
- [ ] Value encoding for every `ColumnType`, NULLs included
      → test: `ProtocolTest.EveryColumnTypeRoundTrips`,
        `ProtocolTest.NullIsDistinguishableFromEmptyString`
- [ ] Errors carry the message, and the position when the source was a `SyntaxException`
      → test: `ProtocolTest.SyntaxErrorCarriesPositionOverTheWire` — [P3](P3.md)'s
        error quality survives the network boundary, or it was pointless

### 9.2 — Server and sessions

- [ ] `Server` — accept loop over `asio::io_context`
      → `src/network/server.cpp`
      → test: `ServerTest.AcceptsAConnection`,
        `ServerTest.ShutdownClosesActiveSessions`
- [ ] `Session` — per-connection state, `shared_from_this` lifetime, its own
      `Transaction*` from [P5](P5.md)
      → `src/network/session.cpp`
      → test: `SessionTest.EachSessionHasItsOwnTransaction`,
        `SessionTest.DisconnectMidTransactionAborts` — a dropped connection must not
        leave locks held forever
- [ ] Thread pool: `io_context` run on N threads
      → test: `ServerTest.HandlesConcurrentConnections`
- [ ] Graceful shutdown: stop accepting, drain, close
      → test: `ServerTest.NoLeakedThreadsAfterShutdown`

### 9.3 — Client library

- [ ] `Client` — connect, `Execute(sql) -> ResultSet`, disconnect
      → `include/network/client.h`, `src/network/client.cpp`
      → test: `ClientTest.ExecuteReturnsRows`,
        `ClientTest.ServerErrorSurfacesAsException`,
        `ClientTest.ReconnectAfterServerRestart`
- [ ] Timeouts, so a hung server does not hang the client forever
      → test: `ClientTest.ExecuteTimesOut`

### 9.4 — CLI REPL

- [ ] Replace the current echo loop with a real REPL over the client
      → `cli/main.cpp`
      → test: `CliTest.ExecutesAStatementAndPrintsRows` — drive it as a subprocess with
        piped stdin/stdout
- [ ] Multi-line input: accumulate until `;`
      → test: `CliTest.MultiLineStatementIsAccumulatedUntilSemicolon`
- [ ] History and line editing via replxx
      → `CMakeLists.txt`, `cli/main.cpp`
- [ ] Dot-commands: `.help`, `.tables`, `.schema <t>`, `.mode <m>`, `.quit`, `.timer`
      → test: `CliTest.DotTablesListsTables`, `CliTest.UnknownDotCommandIsDiagnosed`
- [ ] Errors print with position, pointing at the offending token — the payoff for
      [P3 item 3.5](P3.md#35--error-reporting)
      → test: `CliTest.SyntaxErrorPrintsCaretAtColumn`

### 9.5 — Output formats

- [ ] `table` — aligned columns, correct widths
      → `src/network/protocol.cpp` or `cli/format.cpp`
      → test: `FormatTest.TableAlignsColumnsToWidestValue`,
        `FormatTest.TableHandlesEmptyResultSet`
- [ ] `json` — one array of objects, correctly escaped
      → test: `FormatTest.JsonEscapesQuotesAndBackslashes`,
        `FormatTest.JsonNullIsLiteralNull`
- [ ] `csv` — RFC 4180 quoting
      → test: `FormatTest.CsvQuotesFieldsContainingCommasAndNewlines`
- [ ] Unicode-safe width calculation in `table` mode, or a documented ASCII-only limitation
      → test: `FormatTest.MultiByteCharactersDoNotBreakAlignment`

### 9.6 — Concurrency, end to end

The test that would have been impossible without [P5](P5.md)'s page latch.

- [ ] N clients issuing overlapping read and write transactions against one server
      → `tests/integration/server_test.cpp`
      → test: `ServerConcurrencyTest.ConcurrentReadersAndWritersSerialise` — assert the
        final state is consistent with *some* serial order, not with a fixed expected one
      → test: `ServerConcurrencyTest.NoDeadlockUnderMixedWorkload`
      → test: `ServerConcurrencyTest.TsanCleanUnderConcurrentLoad`

### 9.7 — Settle the name

[§6.2](../ROADMAP.md#62-naming--pick-one): `Axolotl` (repo) · `AxolotlDB` (namespace, CMake
target) · `AxolotlDB` (CMake project, docs) · `AxolotException` (exception base). Four
spellings of one name. *"Nobody but you can make this call; make it before P9 puts a name in
a wire protocol and a CLI banner."*

- [ ] Pick one canonical spelling and write it down
      → `README.md`, [`../ROADMAP.md`](../ROADMAP.md#62-naming--pick-one)
- [ ] Rename consistently: namespace, CMake project and target, exception base, banner,
      protocol handshake string
      → `CMakeLists.txt`, `include/`, `src/`
      → verify: `git grep -in 'axolot' | grep -v <canonical>` returns only intentional
        historical references
- [ ] **Do this before 9.1's handshake ships a string**, not after

## Gate

[§5 P9](../ROADMAP.md#p9--client--server--cli-m) states no explicit gate. Deriving one in
the same spirit:

- [ ] A client connects over TCP, runs the [P4 gate query](P4.md#gate) (join + filter +
      `GROUP BY`), and receives correct rows in all three output modes
- [ ] Multiple concurrent clients run overlapping transactions with a consistent final
      state and no deadlock
- [ ] The CLI executes a script from stdin and produces byte-identical output across runs
      → `tests/integration/server_test.cpp`
      → test: `ServerGate.ConcurrentClientsExecuteCorrectlyOverTcp`

## Done when

1. [ ] The gate test passes, and demonstrably failed before the work.
2. [ ] All seven CI surfaces green — including the server tests on Windows, where asio,
       socket shutdown and subprocess-driven CLI tests all behave differently.
3. [ ] No new compiler warnings; ASan, UBSan and TSan clean.
4. [ ] [ROADMAP §1.1](../ROADMAP.md#11-the-one-page-table) updated;
       [§6.2](../ROADMAP.md#62-naming--pick-one) resolved and struck.
