## The four lessons

### 1. Trust nothing that came off disk

Every blocking finding except N2 is a variant of this. [A2](../ROADMAP.md) found it in
`Tuple` and fixed it thoroughly; [N1](../ROADMAP.md#n1--page-never-validates-a-header-or-slot-entry-that-came-off-disk)
is the identical bug in `Page`, missed because the audit's scope was the serialisation
layer and nobody asked the same question one level down.

The generalisation, and it applies to every format [§4](../ROADMAP.md#4-on-disk-format-catalogue)
lists: **a size or offset that has been to disk and back is untrusted input.** B+Tree nodes
(P6), WAL records (P5) and the HNSW graph (P7) each get a `ValidateOrThrow` of their own,
or they inherit N1.

### 2. Silent wrong answers are the failure mode to engineer out

B2's argument for the vector heap's design, B5's argument for `heap_id` in `VectorRef`,
and N8's overflow finding are all the same principle. A truncated vector returned with no
error is worse than a crash, because nothing downstream can tell.

Carried forward as [invariant 3](../ROADMAP.md#32-the-four-load-bearing-invariants):
*a reference carries proof of what it refers to.*

### 3. A test that asserts nothing is worse than no test

[N14](../ROADMAP.md#n14--minor) found five suites containing only `SUCCEED()`. A green
suite that proves nothing is exactly how C2 survived. This is why every checklist item in
these files names a test, and why `audit.md` section E's rule is stated as *a phase is
complete when a test proves the behaviour, not when the file exists.*

The corollary that P1 also demonstrates, in `tuple_test`: assert on **raw bytes**
independently of `Deserialize`, so a bug in one cannot hide behind a matching bug in the
other. That technique is worth reusing for every format in [§4](../ROADMAP.md#4-on-disk-format-catalogue).

### 4. Compile where the tests run

[N2](../ROADMAP.md#n2--stdformat-without-include-format) — one `std::format` call — meant
six of seven CI surfaces never compiled. The 144 tests were only ever green on MSVC. A
local green is not a green.

## The reading that would have caught N1

Worth doing now if you have not, because P2 revisits every one of these structures:

- **Petrov, *Database Internals*, ch 3 — "File Formats".** Slotted pages, cell layout, and
  the treatment of page-header fields as untrusted.
- **[SQLite database file format §1.6](https://www.sqlite.org/fileformat2.html)** — the
  b-tree page header, with an explicit valid range documented for every field. Read it
  next to `include/storage/page.h` and the gap is obvious.
- **15-445 Fall 2025, Lecture 3 — Database Storage I**
  ([playlist](https://www.youtube.com/playlist?list=PLSE8ODhjZXjYMAgsGH-GtY5rJYZ6zjsd5)).

Project-local: [`../storage_learning_guide.md`](../storage_learning_guide.md) explains the
layer as built. [`../tuple_explained.md`](../tuple_explained.md) is **stale** — it teaches
the pre-A1 format and presents the A1 corruption bug as current behaviour. Do not read it
until [P0 item 0.8](P0.md#08--n12n14-hygiene) rewrites it.
